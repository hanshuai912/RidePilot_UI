# P01 · 欢迎、注册与登录

## 页面目标

新用户建立开发阶段账号并进入建档；已有用户用注册号码和密码登录，继续读取本人计划。

## 依据与范围

- 业务依据：`/data/home/XiaoH/study/xiaoH_xunlian/训练/RidePilot_Product/PRD.md` 的 P01、M01（2026-10-08 更新）。
- 视觉依据：`Agent.md` 与 `references/home-reference.png`。三个页面均无底部五栏，认证成功后才进入建档或首页。
- 交付：[欢迎](P01-welcome.html)、[注册](P01-register.html)、[登录](P01-login.html)。这是可点击设计原型；表单只做本地格式提示，不调用认证接口、不创建账号。

## 信息架构与返回

| 页面 | 第一眼 | 后续信息 | 主要操作与返回 |
| --- | --- | --- | --- |
| 欢迎 | 公路骑行氛围图、训练价值 | 开发阶段号码规则与隐私说明 | 创建账号 → 注册；已有账号 → 登录 |
| 注册 | 11 位号码、设置密码 | 三类字符规则实时反馈、号码未验证说明、隐私说明 | 提交 → 服务端注册 → 初次建档 P02；返回 → 欢迎 |
| 登录 | 注册号码、密码 | 登录数据保护说明 | 提交 → 服务端登录 → 已建档用户首页／未完成建档用户继续 P02；返回 → 欢迎 |

## 校验与反馈

| 条件 | 页面反馈 | 正式实现要求 |
| --- | --- | --- |
| 号码不是恰好 11 位数字 | 输入框错误样式和具体修正提示 | 客户端提示；服务端拒绝，不创建部分账号 |
| 密码只有数字或三类中不足两类 | 实时标出满足类别，提交时提示修正 | 服务端独立校验；数字不计类，空格不是特殊符号 |
| 注册号码重复 | 保留输入，提示该号码无法注册及返回登录入口 | 不创建第二个账号；应考虑防止恶意批量探测 |
| 登录号码或密码错误 | 统一提示“号码或密码不正确” | 保持未登录，不区分账号不存在与密码错误 |
| 网络失败、超时 | 显示未完成与重试，保留输入 | 不显示注册／登录成功，不清除既有用户数据 |
| 服务端校验通过 | 注册进入 P02；登录按档案完成状态进入 P02／首页 | 创建独立 `user_id`；只读取当前账号数据 |
| 重复提交 | 按钮显示进行中并阻止重复请求 | 根据服务端结果恢复可操作状态 |

表单密码默认隐藏，用户可切换显示。正式产品在进入后台或离开认证页时应避免暴露密码。原型不保存输入值或密码。状态消息使用文本与边框，不只依赖颜色。

## 示例与待确认

- 所有输入框初始为空，不提供示例真实号码或密码。
- **已确认**：手动输入 11 位号码；密码至少符合大写、小写、特殊符号三类中的两类；开发阶段不把号码视为已验证手机号。
- **建议方案**：号码仅接受恰好 11 位数字，不做短信验证；该口径与外部 PRD 当前建议一致。
- **待确认**：密码最短长度、特殊符号全集、忘记密码流程、正式用户协议／隐私政策全文及链接、后续手机号验证与旧账号迁移。页面没有擅自新增短信、验证码或第三方登录。

## 验收

- 390 pt 暗色移动端，金色 CTA 与已有首页同一设计系统；输入和按钮点击区至少 44 pt。
- 欢迎、注册、登录三页可互相导航；安全区和小屏滚动正常。
- 号码与密码错误提示可读；纯数字密码不能通过注册规则，本地格式通过不会伪装为已注册成功。
- 登录失败保持未登录；正式后端需做用户数据隔离、密码安全保存与错误尝试限制。
