# A01 · AI 教练首页

## 页面目标

用户从底部「AI 教练」进入，用快捷任务处理训练、饮食或比赛发生的变化，并查看尚未应用的 AI 建议。

## 入口与返回

- 入口：底部「AI 教练」；训练课程的「AI 调整」、饮食替换及赛事变更可带上下文直接进入对应引导流程。
- 本页是一级页面，底部导航固定。引导流程、建议预览、自由对话属于二级页面，返回时保留本页滚动位置；已输入但未保存的内容需要离开确认。

## 信息层级

1. 第一眼：当前关联的正式计划、四项最常用训练调整任务。
2. 继续下滑：餐食替换/新增比赛入口、待处理建议摘要与「预览变化」。
3. 次级入口：建议记录及自由提问；专业数值、参数级差异留在引导页和差异预览页。

## 复用组件

`AppHeader`、`BottomTabBar`、`SurfaceCard`、`AiActionChip`、`AiProposalCard`、`PlanDiff`、`PrimaryButton`、`StatusIndicator`。香槟金仅用于主操作、当前 Tab 与建议状态；风险标识同时使用文字说明。

## 关键交互

| 操作 | 系统反馈 | 去向 / 状态 |
|---|---|---|
| 选择「时间不够」 | 询问可用分钟数，再给缩短/顺延等候选及训练目的影响 | T05 → 草稿 → T06 |
| 选择「感觉疲劳」 | 询问疲劳程度及明显不适；若含胸痛、晕厥等警示，停止常规训练调整建议并提示寻求医疗帮助 | T05 安全分支 |
| 选择「天气变化」 | 询问天气影响与室内条件；无已连接设备时不声称自动控制骑行台 | T05 → 草稿 → T06 |
| 选择「调整日期」 | 选择目标日期，检查时间约束、训练/测试/比赛冲突 | T05 → 草稿 → T06 |
| 选择「替换餐食」 | 先选不喜欢、买不到、外食、准备时间不足等原因，并按过敏/禁忌校验 | N02 → 营养影响预览 → 确认 |
| 选择「新增比赛」 | 收集日期、距离、优先级；先生成训练、测试、饮食影响草稿 | R02 → R03 → 确认 |
| 点击待处理建议「预览变化」 | 显示正式计划与草稿差异、影响范围、冲突及校验结果 | T06；仅用户确认后应用 |
| 查看建议记录 | 显示待处理、已应用、已取消及失败建议，记录来源与时间 | 建议记录页 |
| 自由提问 | 打开有上下文的对话；回答不能直接修改正式计划 | A02；涉及修改时转结构化草稿 |

## 示例数据与一致性

- 画面日期为 **2026 年 10 月 8 日**，与 T01/N01 示例同日。当前正式计划仍是 **60 分钟耐力骑行**，对应的饮食补给也仍按正式计划展示。
- 页面中的 **45 分钟**仅为「时间不够」产生的**未应用示例草稿**，不改变 T01 日历或 N01 补给。本示例表示在 T01/N01 页面快照之后新建了建议。
- 「课程目的与今日补给可能受到影响」是待核对提示，不声称已经完成安全校验、已经变更饮食，或已确认可保持原训练目的。
- AI 生成的候选应限定为 1–3 个，给出简短理由；当前页面只展示建议摘要，不展示伪精确的训练负荷数值。

## 边界状态

| 状态 | 界面处理 |
|---|---|
| 无正式计划 | 上下文卡显示「尚无训练计划」，快捷任务中依赖课程的选项禁用并说明原因；提供建档/创建计划入口 |
| 无待处理建议 | 建议区显示「目前没有待预览的调整」，保留快捷任务和建议记录入口 |
| 正在生成 | 标明收集信息、生成候选、规则校验等阶段；允许退出并保留已输入条件（按产品能力） |
| AI 失败 / 超时 / 离线 | 明确错误和重试入口；正式计划保持不变，可继续手动编辑或查看已有计划 |
| 建议缺字段 / 校验未过 | 不出现「确认应用」；标出需修改参数和原因，支持返回编辑 |
| 基础版本过期 | 提示正式计划已变化，要求基于最新版本重新生成/核对差异 |
| 赛事 / 测试 / 时间冲突 | 标出冲突日期、对象与可选方案，不无提示覆盖 |
| 高风险反馈 | 警示置于主 CTA 之前，阻断高强度方案；提供明确的安全替代与求助建议 |
| 未保存输入 | 返回时提供「继续编辑」「保留草稿」「放弃」 |
| 大字体 / 小屏 | 快捷卡允许文案换行和纵向增高；主要操作不被固定底栏遮挡 |

## 待确认

- 快捷任务的最终排序是否可依据用户行为个性化；当前固定显示训练调整四项。
- 建议记录保留的时长、原始自由文本最小化存储策略及用户删除入口。
- AI 生成时是否支持后台继续并通知用户；当前默认可离开，但不宣称后台运行。

## 验收要点

- A01 首屏以快捷任务为主，自由对话是易找到的次级入口。
- 「正式计划」「未应用草稿」「已应用版本」始终有明确文案，不以颜色单独区分。
- AI 建议先过输入/输出、结构、业务与权限校验，差异预览和用户确认后才可写入计划。
- 模型异常不改变 T01/N01 的正式数据；已完成训练事实记录也不受后续计划调整覆盖。
- 底部五项顺序与 H01/T01/N01 相同；按钮和快捷卡点击目标不低于约 44 × 44 pt。
