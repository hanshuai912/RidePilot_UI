# H01 · 首页

## 页面目标

用户打开 App 后，立即知道今天的正式训练、身体状态信息是否充分、建议吃什么以及当前阶段，并能直达当天最重要的操作。

## 入口与返回

- 入口：登录/首次应用计划完成后；底部「首页」。
- 本页是一级页面，底部五栏导航固定。进入课程、状态反馈、饮食或目标详情后，返回保留首页滚动位置。

## 信息层级

1. 第一眼：日期、今日正式训练的类型、60 分钟总时长、通俗训练目的及「查看今日训练」。
2. 继续下滑：身体状态依据、三餐建议和训练前补给、当前阶段与下次测试。
3. 更深处：未应用的 AI 调整草稿；专业课程区段、完整营养信息和目标趋势在对应模块展开。

## 复用组件

`AppHeader`、`HeroWorkoutCard`、`WorkoutProfileChart`、`StatusIndicator`、`MealCard`、`GoalTimeline`、`AiProposalCard`、`PrimaryButton`、`BottomTabBar`。骑行照片仅用于训练 Hero；图表使用功能灰/雾绿表示 Z1/Z2，香槟金保留给主操作与关键数字。

## 关键交互

| 操作 | 系统反馈 | 去向 / 状态 |
|---|---|---|
| 查看今日训练 | 打开课程目标、完整区段、注意事项和记录入口 | T02 |
| 调整计划 | 选择时间不足、疲劳、天气等原因或手动编辑 | T05/T03；草稿 → T06 差异预览 → 校验 → 用户确认 |
| 记录完成 | 录入完成/部分完成/未完成、实际时长、RPE 与主观感受 | 训练反馈页；事实记录与正式计划分开保存 |
| 点击身体状态 | 选择主观状态并补充必要信息；危险症状进入安全提示 | 状态反馈页；输入后可重新评估 |
| 查看全部饮食/点击补给提示 | 查看三餐和训练前中后补给，必要时替换 | N01/N02；修改仍需预览和确认 |
| 查看目标/点击阶段卡 | 查看长期目标、阶段路线与下次测试 | G01/G03 |
| 点击待处理建议 | 对比正式 60 分钟与草稿 45 分钟，查看训练和饮食影响 | T06；确认前首页仍显示正式 60 分钟 |
| 点击右上头像 | 查看档案、偏好、隐私设置 | M01 |

## 示例数据与依据

- 示例日期：**2026 年 10 月 8 日，周四**，与 T01、N01、A01、M01 一致。
- 正式课程：**60 分钟耐力骑行**。图表为 Z1 热身 **10 分钟** + Z2 稳定骑行 **45 分钟** + Z1 放松 **5 分钟**，总计 60 分钟，强度呈现与 T01 相同。FTP 未录入，首页不显示瓦数。
- 身体状态：**待评估**，因为没有今日主观反馈；没有把训练计划本身推断成「适合训练」的身体结论。
- 三餐为 N01 的建议餐食，**未记录**为实际摄入；食物照片仅作示意，不推断热量或分量。补给建议使用一般性措辞。
- 当前目标为「提升长距离骑行耐力」，阶段「有氧基础」，下一次测试 **10 月 21 日**；不把阶段位置误写为目标能力完成率。
- A01 的 **60 → 45 分钟**是同日稍后生成的**未应用示例草稿**。首页的 Hero、训练日历和饮食补给仍读取正式计划。
- [骑行 Hero 图片](../assets/road-cycling-hero.png)与[三餐图片](../assets/meals-triptych.png)为本轮项目素材；内容数据不取自图片。

## 边界状态

| 状态 | 界面处理 |
|---|---|
| 首次使用 / 无正式计划 | Hero 改为「尚无训练计划」，主按钮进入建档与计划草稿；不显示虚构的课程、阶段或身体结论 |
| 今日休息 | 显示「今天安排休息」，提供下次训练时间；不出现记录完成训练的主按钮 |
| 身体资料不足 | 状态卡显示「待评估」及缺少的依据，允许记录主观反馈 |
| 身体高风险反馈 | 警示置于训练主操作前，提示停止相关训练并寻求专业医疗帮助；不继续生成高强度建议 |
| 加载 | Hero、状态、餐食与阶段分别保持等尺寸骨架，不把上一日内容当作今天 |
| 离线 / 获取失败 | 保留可用的缓存正式计划并标明更新时间；提供重试，不显示未同步草稿为已应用 |
| 饮食禁忌未知 | 三餐区显示待核实提示；成分未确认时不能无提示应用建议 |
| 有比赛 | 在阶段卡前插入下一场比赛卡，展示日期、重要性、备赛状态；无比赛时隐藏 |
| 有待处理草稿 | 独立呈现草稿数量和预览入口；主 Hero、三餐仍为正式数据 |
| 大字体 / 小屏 | Hero 文案换行但图表和主按钮不重叠；页面自然滚动，底栏遵守安全区 |

## 待确认

- 首页默认问候语是否按本地时段变化；当前画面仅展示早晨示例。
- 「记录完成」是否在课程开始前也作为首页次级动作显示；当前设计保留直接入口，具体可按时间与状态调整。
- 首页是否展示训练实际开始时间；当前 PRD 未要求必填，因此不制造时间点。

## 验收要点

- 首页与参考图同属近黑、石墨、香槟金家族，照片克制使用；底部五栏顺序和选中态一致。
- 60 分钟文字、Z1/Z2 图形和 10+45+5 分钟分段一致，无无关高强度区段。
- 身体状态有依据或明确「待评估」；饮食、目标与 AI 建议不将示例/估算冒充事实。
- 草稿不能覆盖正式训练、饮食和已记录事实；用户确认后才生成新正式版本。
- 所有主要点击区域约 44 × 44 pt 以上，主按钮高 52 pt，底部滚动内容不被导航遮挡。
