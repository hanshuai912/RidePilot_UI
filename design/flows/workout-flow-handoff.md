独立 Frame 用于视觉评审，按钮操作以可点击原型为准。原型是**本地模拟交互**，没有接入真实 AI、账户、训练计划或服务端保存。为演示日历与详情往返，原型把**纯示例课程数据**放在本地 URL 查询参数中；生产实现必须通过鉴权后的数据读取和状态管理传递敏感训练资料，不采用 URL 传递真实健康数据。

## 数据与状态来源

| 概念 | 设计示例 / 实现要求 |
|---|---|
| 原正式版本 | `v7`，10 月 8 日 60 分钟耐力骑行；区段为 Z1 10 + Z2 45 + Z1 5 |
| 每周正式计划 | 60 + 60 + 45 + 90 = 255 分钟；只统计本周正式骑行课程 |
| 手动简洁草稿 | 45 分钟，Z1 5 + Z2 35 + Z1 5；本周预览 240 分钟 |
| 专业编辑示例 | 2 ×（工作 4 + 恢复 3）分钟，稳定 Z2 缩至 31 分钟；10 + 14 + 31 + 5 = 60 分钟；目的变化必须明确确认 |
| AI 主方案 | 35 分钟，Z1 5 + Z2 25 + Z1 5；本周预览 230 分钟 |
| AI 备选 | 20 分钟轻松恢复，Z1 5 + Z1 10 + Z1 5；必须标明目的由有氧训练改为恢复 |
| 能力依据 | 主示例 FTP 未录入，不显示虚构瓦数或 TSS；功率编辑条件变体使用标明来源的 FTP 186 W（9 月 16 日手动测试），仅用于展示有可靠基准时的控件 |
| 饮食联动 | 只提示复核补给，不自动修改 N01 正式饮食计划或实际进食记录 |

课程总时长必须由展开后的区段时长派生；图区段、简洁说明、差异和周统计都从同一份数据计算。简洁/专业视图共享草稿，AI 候选被手动微调后保留两个来源信息。

## 页面路由与按钮合同

| Frame | 主要按钮 / 操作 | 跳转与保存语义 |
|---|---|---|
| 01 详情 | 手动编辑 / AI 调整 | 到 02 / 04；正式计划只读，返回到训练日历 |
| 02 简洁编辑 | 专业视图 / 预览修改 / 保存草稿 | 到 03 / 08；保存草稿不应用正式计划 |
| 03 专业编辑 | 简洁视图 / 预览修改 / 保存草稿 | 到 02 / 08；切换不丢区段或顺序 |
| 04 AI 原因 | 选择原因 / 下一步 | 到 05；危险身体症状在后续参数页阻断生成 |
| 05 AI 参数 | 选择必要条件 / 生成建议 | 到 06；原因变化保留已填写的可用参数 |
| 06 生成中 | 取消 / 重试（失败态） | 取消回 05；失败保留输入及正式计划 |
| 07 AI 方案 | 选择候选 / 继续修改 / 预览 | 到 02 或 08；候选均为未应用草稿 |
| 08 差异 | 应用范围 / 继续修改 / 校验并继续 | 回来源编辑页或到 09；校验失败留在 08 并定位原因 |
| 09 确认弹层 | 确认应用 / 返回修改 | 成功到 10；关闭弹层回 08，草稿保留 |
| 10 成功 | 查看新课程 / 返回日历 / 恢复上一版本 | 到 01 / T01 / 恢复提案的 08；恢复需再次到 09 确认 |

深层页面使用顶部返回和底部安全区操作栏，不显示一级五栏导航。课程详情与编辑页支持纵向滚动，底部操作始终可触达。

## 字段、输入和校验

### 简洁编辑

- 日期、开始时段、时长、难度、户外/室内、是否保留目的。修改时长需要重新分配真实区段，不能只改标题数字。
- 日期变更先检查用户可训练时段、时区、已排课程、测试和比赛。本示例没有新的可靠可用时段，因此改期草稿在预览时阻断应用并说明需补充资料。
- 「较难」与新增节奏间歇可能改变训练目的；当「保留原目的」仍开启时阻断应用，用户须明确调整目的或恢复原结构。

### 专业编辑

- 区段保留稳定顺序和唯一 ID。支持区段新增/删除、工作与恢复时长、组数、排序、RPE 与有依据的功率目标。
- 重复组展开后计算总时长。热身、放松、工作、恢复时间必须有效；总时长、训练目的和图表同步更新。
- 功率目标必须带单位、可测量的数据来源与日期。FTP 缺失时使用 RPE，不预填 W/%FTP；有可靠功率基准时可切换目标类型并做范围校验。
- 本原型的功率条件变体展示 **工作段 150 W** 输入，不代表对未录入 FTP 用户的建议。

### AI 与应用

- AI 原因优先用结构化选项；只有「其他原因」显示短文本。生成中展示可理解阶段，不显示虚构百分比。
- 输入安全、输出语义、结构、训练、饮食禁忌、权限和计划版本校验均在应用前执行。胸痛、晕厥等危险反馈阻断常规训练建议。
- `apply_scope` 默认本节；选择联动后续计划必须重新分析受影响日期。若有营养草稿，允许独立选择是否应用；未选择则正式饮食保持原状。
- 客户端应用请求携带基础计划版本及幂等键；服务端应重新校验并事务写入，不能把页面本地校验作为最终授权。

## 建议的数据模型映射

```text
WorkoutDraft {
  base_plan_version
  workout_id, date, timezone, start_time?, scene
  purpose, difficulty, keep_purpose
  ordered_segments[]: {id, type, duration_sec, target_kind, target_value}
  repeat_groups[]: {repeat_count, work_segment, recovery_segment}
  source: manual | ai | ai_then_manual | restore
  status: draft | pending_validation | ready | blocked | applied | rejected | expired
}
```

前端可以用单一结构化草稿作为简洁/专业视图的读写源。计划版本、完成事实和饮食计划分别存储；课程草稿只持有目标资源与允许变更范围。恢复旧内容是新的提案及版本事件，不删除现有版本或训练事实。

## 状态与错误恢复

| 状态 | 产品行为 |
|---|---|
| 未保存退出 | 继续编辑 / 保留草稿 / 放弃修改；放弃不影响正式计划 |
| AI 失败或超时 | 保留原因和参数，重试或手动编辑；正式计划不变 |
| 参数无效 | 错误指向区段、时长、功率依据或日期；阻断确认应用 |
| 版本冲突 | 拉取最新正式版本，重新计算差异并要求用户复核 |
| 保存失败或结果未知 | 保留草稿；先查询幂等申请的处理状态再允许重试，不伪装成功 |
| 应用成功 | 新版本可回读后显示成功；旧版在历史中可见 |
| 恢复版本 | 反向差异 → 校验 → 确认 → 新正式版本，不回滚已完成记录 |

## 组件与视觉规格

- 复用 `AppHeader`、`SurfaceCard`、`Metric`、`WorkoutProfileChart`、`AiActionChip`、`AiProposalCard`、`PlanDiff`、`PrimaryButton`、`SecondaryButton`、`BottomActionBar`、`ConfirmSheet`、`StatusIndicator`。
- 暗色单主题，背景 `#0d0f0e`、容器 `#191c1a`、品牌金 `#d2c18f`；Z1 灰、Z2 雾绿、Z3 暖金分别承担区段语义，警告配文字与图标。
- 主按钮高 52pt，其他点击目标不少于约 44 × 44pt；页面以 390pt 宽设计，支持自然滚动、系统字体放大和底部安全区。
- 图表提供区段文字、横轴时长与强度依据；没有可靠 FTP 时，不输出瓦数或精确训练负荷。

## 原型验收

1. 从 `training-flow-entry.html` 点「查看课程」，经手动 45 分钟路径应用后返回日历，日历卡显示 45 分钟，本周合计 240 分钟。
2. 从详情选择 AI「时间不够」35 分钟，选择方案 A 后预览 60→35、255→230，确认后正式版本从 v7 到 v8。
3. 在成功页点「恢复上一版本」，经过反向预览与再次确认后形成 v9，课程回到 60 分钟、本周 255 分钟，v7/v8 留在历史中。
4. 专业编辑增加两组 4+3 分钟间歇后，稳定段变为 31 分钟，总计仍 60 分钟；未确认目的变化时不能应用。
5. 验收侧栏的放弃、AI 失败、无效参数、网络错误和恢复入口均可复现对应状态。

静态 HTML 结构、JavaScript 语法与上述状态转换已做本地检查。当前环境的浏览器截图进程受限，因此尚未完成截图目视验收；请以浏览器打开高保真 HTML 做最终视觉评审。
